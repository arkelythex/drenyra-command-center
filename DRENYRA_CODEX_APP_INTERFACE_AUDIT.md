# Drenyra Codex App Interface Audit

**Last updated**: 2026-07-07

## Executive summary

Drenyra already has the right foundation for a Codex-like product: an agentic shell, a persistent sidebar, a bottom command bar, a command center, and an artifact feed.

The main gap is not visual polish. The main gap is product posture: Drenyra must behave less like a module dashboard with chat attached, and more like a fiscal workbench where conversation, evidence, agent runs, approvals, and audit trails are the primary workflow.

## Target philosophy

Drenyra should feel like:

> A calm fiscal command center where humans direct agents, agents produce verifiable artifacts, and every fiscal decision remains scoped, reviewable, and auditable.

Drenyra should not feel like:

> A traditional ERP dashboard with an assistant bolted onto the side.

## Current foundation

Verified existing pieces:

- `apps/web/src/components/agentic-shell/AgenticLayout/AgenticLayout.tsx`
  - Provides a three-panel shell: sidebar, main content, right inspector.
  - Already includes an always-visible `AgenticCommandBar`.
- `apps/web/src/components/agentic-shell/AgenticCommandBar/AgenticCommandBar.tsx`
  - Supports text input, `@` references, `/` commands, and thread creation.
- `apps/web/src/components/agentic-shell/AgenticSidebar/`
  - Provides a collapsible left navigation shell.
- `apps/web/src/features/drenyra-command-center/components/ArtifactFeed/`
  - Collects artifacts from cognitive messages and renders them as a chronological feed.
- `apps/web/src/features/drenyra-command-center/components/DrenyraCommandCenter.tsx`
  - Uses chat as the primary UI and places artifacts in the right panel.

## Gaps to fix

### 1. Sidebar still reads like module navigation

Current sections such as `TABLERO`, `PARTES`, and `SISTEMA` are cleaner than a legacy ERP menu, but they still describe modules more than active work.

Target:

- New case / new thread first.
- Search second.
- Active company and fiscal period always visible.
- Recent fiscal work threads grouped by company/case.
- System tools moved lower and visually quieter.

### 2. Command bar needs fiscal context and safer submission

The command bar is structurally right, but it needs stronger fiscal safety.

Required improvements:

- Display the active company, RUC, and fiscal period near the input.
- Remove hardcoded company IDs from thread creation.
- Use the active scoped company context.
- Treat `/` commands as commands, not `@` tags.
- Add a visible agent/model selector only when it changes behavior.
- Add attachment affordance for evidence upload.

### 3. Artifact feed needs fiscal metadata

Artifact cards are currently compact, but they do not yet expose enough fiscal context.

Each artifact card should show, when available:

- artifact type;
- title;
- status;
- source;
- company/RUC;
- period;
- evidence count;
- generated by agent;
- review/action state.

### 4. Right panel should be an inspector, not only a feed

The right rail should behave as a contextual inspector.

Recommended modes:

- `Artifacts`
- `Evidence`
- `Audit trail`
- `Agent run`
- `Fiscal scope`

### 5. Main content should reduce dashboard noise

The main command center should prioritize:

1. current task;
2. agent response;
3. artifacts produced;
4. next human decision.

### 6. Agent state should be explicit

Every long-running fiscal operation should expose clear state:

- queued;
- reading evidence;
- validating SUNAT/SIRE assumptions;
- generating artifact;
- waiting for human approval;
- completed;
- failed with reason.

### 7. Fiscal safety must remain visible

Drenyra must always make the fiscal scope visible before action:

- organization;
- company;
- RUC;
- period;
- country;
- evidence source;
- approval owner.

## Implementation plan

### Phase 1 — Shell alignment

- Reframe sidebar labels around active work, not modules.
- Add a compact active fiscal scope block to the sidebar.
- Keep system/configuration items visually secondary.
- Ensure mobile drawer mirrors desktop behavior.

### Phase 2 — Command bar hardening

- Inject active company context into `AgenticCommandBar`.
- Remove hardcoded `companyId`.
- Separate `/command` insertion from `@reference` insertion.
- Add fiscal scope preview above or inside the command bar.
- Add evidence attachment entry point.

### Phase 3 — Artifact-first inspector

- Extend artifact cards with fiscal metadata.
- Add empty state copy that teaches the user what artifacts will appear.
- Add artifact actions: inspect, approve, request explanation, export when supported.
- Add selected-artifact inspector state.

### Phase 4 — Agent run transparency

- Surface agent execution state in the chat timeline.
- Show which agent produced each artifact.
- Link agent output to evidence and audit logs.
- Add failure states with recovery actions.

### Phase 5 — Interaction polish

- Reduce visual noise in the main command center.
- Normalize spacing, muted borders, and calm surfaces.
- Prefer progressive disclosure over dense panels.
- Verify keyboard navigation and focus states.

## Acceptance criteria

- A user can start meaningful fiscal work from the command bar without visiting a module page first.
- Every generated artifact shows enough fiscal context to be safely reviewed.
- The active company/RUC/period is visible before risky fiscal actions.
- The right panel explains the current work item, artifact, evidence, or agent run.
- The sidebar feels like active work history, not a static app menu.
- There are no hardcoded tenant/company IDs in command submission.
- The interface stays calm: low chrome, clear hierarchy, minimal dashboard noise.

## Risks

- Do not copy Codex visually without preserving fiscal safety.
- Do not hide company/RUC/period context for minimalism.
- Do not make agent actions feel magical or opaque.
- Do not create artifacts without evidence and audit linkage.
- Do not broaden navigation again after simplifying the shell.

## 1. Decisión ejecutiva

Drenyra tratará los errores fiscales como **eventos recuperables con ruta de acción**, no como mensajes técnicos. Cada error tiene una clasificación (recoverable/irreversible/unknown), un recovery path asociado, y produce evidencia de resolución. Los errores `recoverable` reciben auto-retry con exponential backoff; los `irreversible` guían al usuario a acción compensatoria.

Catálogo inicial de 20 códigos de error (E01–E20) cubriendo: SUNAT, cálculo, documentos, conciliación, aprobaciones, sesión, conectividad y consistencia de datos.

## 2. Problema

- Mensajes de error genéricos ("Error 500") sin causa ni acción sugerida
- Sin distinción entre error recuperable vs irreversible
- Sin integración con audit trail ni evidencia de resolución
- Costo fiscal real: multas por errores ignorados, duplicidad, rectificatorias innecesarias

## 3. Taxonomía de errores

```
RECOVERABLE
├── RETRYABLE      → reintento automático (SUNAT timeout, red)
├── CORRECTABLE    → acción correctiva específica (RUC inválido, IGV mismatch)
└── COMPENSABLE    → requiere NC, ND o ajuste (detracción faltante)

IRREVERSIBLE
├── DATA_LOSS       → datos perdidos sin recuperación
├── DEADLINE_PASSED → plazo fiscal vencido
└── INVALID_STATE   → estado inconsistente sin corrección

UNKNOWN
├── TRANSIENT       → error temporal (timeout, rate limit)
└── PERMANENT       → error permanente sin clasificar
```

## 5. UI Components

- **Error Banner (inline)**: rojo/ámbar según severidad, badge de tipo (RECUPERABLE/IRRECUPERABLE), botones (Reintentar/Ver detalle/Ignorar). L1+: sugerencia de acción.
- **Error Toast (temporal)**: critical 30s, warning 15s, info 8s. Botón "Ver detalle". No se cierra en critical sin acción.
- **Error Detail Panel**: flyout con código, timestamp, RUC+periodo, causa probable, recovery path con pasos ordenados, evidence snapshot.
- **Error List** (`/errors`): tabla con filtros por tipo/severidad/categoría/RUC/periodo/estado, URL state persistente, export CSV.

## 6. Recovery Paths

| Path | Errores | Pasos | Riesgo |
|---|---|---|---|
| RETRY_CDR | E01 | 3 pasos (verificar → reintentar → validar) | none |
| FIX_SUNAT_DATA | E02, E03, E04 | 3 pasos (revisar → corregir → reenviar) | low |
| RECALCULATE_IGV | E05 | 3 pasos (verificar base → recalcular → validar) | low |
| ADD_DETRACTION | E06 | 3 pasos (calcular → depositar → vincular) | medium |
| FIX_RETENTION | E07 | 3 pasos (verificar tasa → corregir → recalcular) | low |
| REOPEN_PERIOD | E08 | 4 pasos (solicitar → aprobar G4 → corregir → cerrar) | high |
| FILL_CORRELATIVE | E09 | 3 pasos | medium |
| DEDUPLICATE | E10 | 3 pasos | low |
| RECONCILE_BALANCE | E11 | 4 pasos | medium |
| REAUTHENTICATE | E13 | 2 pasos | none |
| QUEUE_OFFLINE | E14 | el sistema encola y reintenta | none |
| BACKOFF_RETRY | E15 | esperar + reintentar automático | none |
| RESOLVE_CONFLICT | E17 | 4 pasos | medium |
| COMPENSATE_NC | E06, E11, E20 | 3 pasos (emitir NC → vincular → sustentar) | high |
| ESCALATE | E16 | contactar soporte con ID de error | high |

Cada RecoveryPath tiene: id, errorCode, label, steps[], risk, requiresApproval, approvalGate, estimatedTime.

## 7. Estados del error

| Estado | Significado | Acción |
|---|---|---|
| pending | No atendido | Recovery path disponible |
| in_progress | Recuperación iniciada | Continuar/cancelar |
| resolved | Corregido | Ver evidencia |
| compensated | Compensado | Ver evidencia de compensación |
| ignored | Usuario ignoró | Reabrible |
| escalated | Escalado a soporte | Ticket de referencia |
| expired | Ventana vencida | Sin acción posible |
| auto_resolved | L3 resolvió automáticamente | Ver evidencia |

## 6. Reglas de negocio

1. Error dedup: mismo `code + RUC + periodo + metadata_hash` en 5min = mismo error. Count > 3 en 15min escala a critical.
2. L3 solo para errores `recoverable` con confianza > 0.9 y ventana de reversión activa.
3. Offline queue: IndexedDB (máx 200), replay FIFO al reconectar. Si replay falla → pending.
4. Auto-retry: exponential backoff 5s/15s/45s para SUNAT_TIMEOUT.
5. Error banner recibe focus automático (WCAG 2.4.3).
6. Ctrl+E abre centro de errores desde cualquier pantalla.

## 7. L0–L3 Mapping

| Nivel | Comportamiento |
|---|---|
| L0 — Explain | Error detectado, explicado en lenguaje natural con causa probable |
| L1 — Recommend | Error + 1-3 sugerencias ordenadas por probabilidad |
| L2 — Prepare | Error + acción correctiva pre-llenada lista para revisar |
| L3 — Execute | Error corregido automáticamente (solo recoverable, confianza > 0.9) |

## 1. Decisión ejecutiva

Drenyra presentará toda información fiscal con **evidencia integrada por defecto**. Cada valor fiscal (número, tabla, indicador) debe incluir: fuente, método de cálculo, estado de verificación y nivel de confianza. El badge de evidencia es parte del data display, no un tooltip decorativo.

Cinco principios: la fuente es parte del dato, el badge de confianza es parte del componente visual, el desglose no es un lujo, datos sensibles se marcan visiblemente, y lo no verificado tiene representación visual distinta sin depender solo de color.

## 2. Problema

Los sistemas fiscales presentan datos en crudo sin contexto probatorio. Cuando un contador ve una cifra no sabe de dónde vino, cómo se calculó, si está verificada o si puede confiarla para una declaración. Esto causa: pérdida de 5-15 min rastreando orígenes, declaraciones con datos no verificados, y dependencia de confianza institucional en vez de confianza verificable.

## 3. Principios de contenido

**P1 — La fuente es parte del dato.** Todo valor fiscal muestra: fuente (SUNAT/usuario/AI/derivado/configuración/regla), estado (verificado/pendiente/conflictivo/no verificado/error), y confianza (baja/media/alta/definitiva).

**P2 — El badge de confianza es parte del data display.** Visible en el componente de dato, no oculto en hover o tooltip.

**P3 — El desglose no es un lujo.** Cálculos multi-paso (IGV, detracción) expandibles para mostrar cada sub-operación con su propia fuente y confianza.

**P4 — Lo no verificado se ve diferente.** Valor pendiente de verificación tiene representación visual distinta de uno verificado — icono + texto + color, no solo color.

**P5 — El contexto persiste en exportación.** PDF/CSV/JSON exportados incluyen metadatos de evidencia (fuente, timestamp, RUC, período) en header o metadata del archivo.

## 4. L0–L3 Content Presentation

| Nivel | Muestra | Cuándo se usa |
|---|---|---|
| L0 | Valor + badge estado + fuente abreviada | Tablas, resúmenes, dashboard — instantáneo |
| L1 | L0 + badge expandido con source, método, timestamp | Hover/click en badge, primera expansión |
| L2 | L1 + breakdown completo, evidence IDs, links a raw data | Panel lateral o modal dedicado |
| L3 | L2 + datos crudos embedidos (XML SUNAT, CDR PDF, JSON) | Forense, auditoría, resolución de disputas |

## 5. Jerarquía H1–H5

| Nivel | Componente | L0 badge | Interacción |
|---|---|---|---|
| H1 | Page title / dashboard metric | Integrado | Click → L1 panel |
| H2 | Card / section header | Inline | Hover → tooltip expandido |
| H3 | Table cell | Compacto | Click → L1 inline |
| H4 | Detail field | L1 por defecto | Expande a L2 |
| H5 | Raw data viewer | L2+ completo | Navegación a L3 viewer |

## 6. Formato canónico de número fiscal

```
S/ 15,234.00  ✓ Verificado  SUNAT
S/ 3,200.00   ○ Pendiente   Usuario (15/07/2026)
S/ 8,100.50   ⚠️ Conflictivo  Derivado
S/ 45,000.00  — Sin verificar  AI
```

En comparaciones, cada valor lleva su propio badge:

```
Declarado:  S/ 15,234.00  ✓ Verificado  SUNAT
Calculado:  S/ 15,210.00  ✓ Verificado  Regla (IGV 18%)
Diferencia: S/ 24.00      • Explicable
```

## 7. Estados de presentación

| Estado | Visual | Comportamiento |
|---|---|---|
| Loading | Skeleton específico, tiempo estimado si > 3s | No oculta otros datos verificados |
| Empty | "Sin datos" + sugerencia de acción | Distinto de "no verificado" |
| Error | Último valor conocido + error banner | Reintentar + ver datos locales |
| Edge: fuente mixta | Badge "Mixto" + breakdown por componente | L1 expandible |
| Edge: confianza baja único | Badge "Sin verificar" + "Única fuente disponible" | — |
| Edge: recién actualizado | Badge "Actualizado" con timestamp (5 min) → transición a normal | — |
| Edge: múltiples RUC | Cada valor mantiene su badge RUC + evidencia | — |

## 8. Trust indicators por entidad

| Entidad | Display | Indicador |
|---|---|---|
| Documento (factura) | Badge por línea + total | Estado SUNAT |
| Declaración | Badge por tributo + consolidado | Estado (presentada/rectificada) |
| Tributo (IGV, Renta) | Badge por período + breakdown | Estado deuda |
| Período fiscal | Badge resumen + detalle | Estado (cerrado/abierto) |
| RUC | Badge estado SUNAT | Activo/suspendido/baja |
| Detracción | Badge por operación + acumulado | Estado SPOT |
| Conciliación | Badge por diferencia | % coincidencia |

## 9. WCAG para evidencia

- Badge sin color: icono + texto descriptivo (1.4.1)
- Contraste: AA 4.5:1, target AAA 7:1 (1.4.3/1.4.6)
- Lector pantalla: `aria-label="IGV: 15,234 soles, verificado, fuente SUNAT"` (4.1.2)
- Live region en cambio de estado: `role="status"` (4.1.3)
- Navegación L0→L1→L2: Enter expande, Escape cierra (2.1.1)
- Print: badges como texto, tooltips inlineados, URLs completas (1.4.10)

## 10. Reglas de negocio

1. L0 ocupa < 80px en línea y es instantáneo (< 50ms render)
2. L1-L2 cargan lazy con skeleton; timeout > 3s mustra indicador
3. Badge de evidencia se muestra en todo valor fiscal sin excepción justificable
4. Exportación PDF incluye metadatos de evidencia en header de cada página
5. Datos migrados sin origen: badge "Sin fuente" + workflow para asignar fuente manual
